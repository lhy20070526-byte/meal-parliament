# 🍽️ 外卖/做饭决策议会

面向中国大陆用户的中文用餐助手。五位虚拟专业顾问分别照顾营养、预算、时间精力、冰箱食材和口味，餐桌主持人整理分歧并给出具体菜品和做法。金额为人民币，用餐时间默认为北京时间。

## 怎么使用

1. 选择“直接说需求”：写下今晚的想法，点击“帮我整理需求”，在线服务将明确提到的信息填入表单；没有提到的项目保留原值，原话也会交给顾问。
2. 或选择“按问题填写”：用选择题填写做饭、买菜意愿，用填空题填写本餐预算、食材、口味。饥饿程度是1—10分滑条，拖动时表情从轻松变为期待开饭、饿瘪，数字与表情即时变化。两种方式都能在开始前修改。
3. 可以上传或拍摄冰箱照片，点击“识别这张照片”后才会发送给服务。先检查或修改食材名称、数量，再点击确认加入清单。
4. 点击“开始商量今晚吃什么”，查看顾问讨论、方案比较和今晚吃什么。最终可以保存中文用餐建议。

不再提供加班夜、冰箱空了、减脂等预设场景按钮。减脂仍可由用户主动选择为饮食要求。预算仅询问这一餐最多花多少，不询问工资和收入。

## 安装与运行

需要 Python 3.11+。在项目根目录执行：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

复制 `.env.example` 为 `.env` 可配置真实模型。应用支持 `LLM_PROVIDER=deepseek`（固定官方地址 `https://api.deepseek.com`，默认模型 `deepseek-flash`）和 `LLM_PROVIDER=openai`，两者分别读取各自的 key；原有 `OPENAI_API_KEY`/`OPENAI_MODEL` 仍兼容。推荐把本机配置写入 `~/.config/meal-parliament/.env`：

```dotenv
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=你自己的key
DEEPSEEK_MODEL=deepseek-flash
PARLIAMENT_MODE=auto
```

配置优先级为当前进程环境、本机配置文件、项目 `.env`；应用使用 `dotenv_values` 读取，不会把 key 写入全局环境、trace 或界面。编辑本机配置后刷新页面即可生效。侧栏的“检查服务连接”按钮只在已配置时可用，点击后才发出一条不超过64 token的短请求。没有当前提供商 key 时，`auto` 自动进入本地 mock；显式 `PARLIAMENT_MODE=real` 会给出缺 key 错误而不会静默替换。真实模式的输入可能发送给对应模型服务，请在演示前告知参与者。

已完成真实服务连接、需求整理、示意图片识别和完整讨论流程验证；48项回归测试通过。真实照片效果仍需实拍确认。


## 离线体验

没有密钥时仍可手动填写并运行完整示例讨论，页面明确显示“示例体验”。自由描述的在线整理不可用时会提示手动填写，不会伪装已理解。示例食材不代表识别上传照片。真实服务出错不会悄悄替换成示例结果。

## 多顾问协作

用户需求 → 五位顾问分别提出意见 → 主持人整理冲突并调整关注程度 → 引用其他顾问的意见继续商量 → 汇总可行吃法 → 五位顾问分别评价 → 按当前关注程度计算结果 → 给出建议。

两种方案相差不足百分之十时会再商量一轮。预算、禁止做饭、禁止买菜和明确的食材安全要求优先于评分；可行方案不足时最多重新整理一次，仍不足则明确说明。

内部保留结构化发言、引用、方案、评分及决定，方便核验；用户界面只显示中文建议，不展示代码、原始数据或内部编号。主要模块为输入页面、需求整理、图片识别、顾问与主持人、流程编排和显示组件。

## 演示建议

先请观众用自己的话提出需求，展示预算与意愿自动填入；再上传食材照片，修改一项识别结果并确认。开始讨论后，让观众观察顾问之间的不同意见，最后查看菜品、花费、步骤。可手动修改预算或意愿重新商量，比较结果。

## 限制与验证

照片不能确定新鲜程度、保质期或看不见的食材；用户需要确认。当前真实识图验证使用标明为示意图的测试图片，尚不等于真实冰箱照片识别准确率验证。摄像头需要用户自行授权。

食材与禁忌筛选采用保守规则，不是完整配料认证；价格和营养为估计。应用不会代替用户下单、付款或发布内容。本机运行记录和账号交接文件不随源码上传。
